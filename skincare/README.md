# skincare/ — スキンケア管理

30歳男性・MARK-VU 肌診断（2026-08-12）とポテンツァ（RFマイクロニードリング）施術を
起点とした、**年単位のスキンケア管理**。

Health OS の6つ目の柱として、ラン・筋トレ・体調と同じ枠組みで運用する。
つまり「何をやったか」を記録し、「効いたか」を決まった間隔で判定し、
判定に応じて次の一手を決める。感覚で製品を足し引きしない。

## いま何をすればいいか（迷ったらここだけ）

1. **毎朝、酸化鉄配合の色つき日焼け止めを2本指分（0.8〜1g）。** 他を全部やめてもこれだけは続ける
2. **施術後7日は Torriden ＋ セラミドクリームだけ。** goodalパッドとRoCレチノールには触らない
3. **新しいものは2週間に1つだけ足す。** ナイアシンアミド5% → ビタミンC → レチナール週2回の順

**処方の本体は [01-protocol/master-plan.md](01-protocol/master-plan.md)**
（6か月の完成形・導入順・洗顔とクレンジング・インナーケア）。
**今月の具体的な動きは [01-protocol/month-01_2026-08-14.md](01-protocol/month-01_2026-08-14.md)**。

長期の位置づけは [01-protocol/schedule.md](01-protocol/schedule.md)、
時期を問わない完成形の手順は [01-protocol/daily.md](01-protocol/daily.md)。

## フォルダの構成と、なぜこの形なのか

```
skincare/
├── 00-baseline/          不変の記録。あとから書き換えない
│   └── 2026-08-12_markvu.md
├── 01-protocol/          いま実行するもの。変わり続ける
│   ├── master-plan.md        ★処方の本体。6か月の完成形・洗顔・インナーケア
│   ├── month-01_2026-08-14.md  1か月の具体的な動き（8/14〜9/13）
│   ├── daily.md              毎日の手順（時期を問わない完成形）
│   ├── schedule.md           長期計画と判定日
│   ├── rules.md              やらないこと・他の柱との両立
│   ├── dark-circle-test.md   くまの型判定（5分・1回やれば済む）
│   ├── CHANGELOG.md          いつ・何を・なぜ変えたか（追記のみ）
│   └── archive/              差し替えた旧版
├── 02-products/          製品台帳
│   ├── current.md
│   └── archive/
├── 03-log/               時系列の記録。追記のみ
│   └── 2026-08.md
└── .private/             顔写真・診断書原本（git 管理外）

../docs/skincare-research.md   根拠。処方を変えるときはここに戻る
```

エビデンスだけ `docs/` に置いているのは、このリポジトリが既に
`docs/sub3-research.md`・`docs/strength-research.md` を研究ノートの置き場としているため。
ここだけ別系統にすると参照先が二重化する。

設計の原則は3つ。

**① 「変わらないもの」と「変わるもの」を混ぜない。**
診断結果（`00-baseline/`）は事実の記録で、あとから書き換えてはいけない。
一方いま何を塗っているか（`01-protocol/`）は毎月変わる。
これを1つのファイルに書くと、3か月後に「当時どうだったか」が復元できなくなる。
番号プレフィックスは、この「不変 → 実行 → 記録 → 根拠」の順序を固定するためのもので、
ファイル一覧を開いたときに常に同じ並びになる。

**② 記録は追記のみにする。**
`03-log/` は月ごとに1ファイル。過去の月のファイルは編集しない。
「先月は調子が良かった気がする」を検証できる状態を保つ。

**③ 根拠と実行を分ける。**
`01-protocol/` には「何をするか」だけを書き、「なぜそうするか」は
`../docs/skincare-research.md` に置く。毎朝読むファイルに論文の話が混ざっていると、続かない。
逆に処方を変えるときは必ずそちらに戻る。

**④ 変えた記録を残す。**
`01-protocol/` は上書きされ続けるので、Git 履歴とは別に
`CHANGELOG.md` に「いつ・何を・なぜ」を追記する。
3か月後に「なぜこの製品をやめたんだっけ」を思い出せる状態を保つ。

なお、スキンケアそのものは終わりのない **Area**（維持する基準）であって
期限つきの Project ではない。「12週間の集中ケア」のような期限つきの取り組みが出てきたら、
そのときに `99-projects/` を足す。最初から作らない。

## 公開と非公開の線引き

**このリポジトリは public。** `main` から GitHub Pages が配信されている。

| 種類 | 置き場所 | 理由 |
|---|---|---|
| 測定値（毛穴72、ブラウン色素27 …） | リポジトリ | 本人が公開を選択済み。数値だけでは個人を特定しない |
| 実行計画・製品台帳・エビデンス | リポジトリ | 公開して困るものではない |
| **顔写真・診断書PDF原本** | **`.private/` と Google Drive のみ** | 取り消しがきかない |
| クリニックの施術記録・領収書 | 同上 | 同上 |

一度 push した画像は履歴に残り、あとから削除してもコミット履歴から復元できる。
顔写真はこの「取り消せなさ」のコストが高すぎるので、技術的にではなく
**設計として**入れない。`.gitignore` はその線引きを機械で担保するためのもの。
